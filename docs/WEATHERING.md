# ジオメトリフィールドと手続き的経年変化（Phase 4）

**実施日**: 2026-08-10
**成果物**: D1（ヒーローアセットのリアルタイム描画）、D2（形を変えると摩耗が追従する連番）

---

## 1. 結論から

**1280×720 の iGPU（Radeon RDNA2 / VRAM 1GB）で、4 種類のフィールドを毎ピクセル導出しても
コストは +18〜41% で済む。**

| シーン | プレーン | フィールド + 経年変化 | 増分 |
|---|---|---|---|
| `hero_flange`（23 ノード） | 2.74 ms | **3.22 ms** | +18% |
| `pettobotoru`（69 ノード） | 6.97 ms | **9.86 ms**（101 fps） | +41% |

計測は 3 回実行の最小値（[SPIKE_PERF.md](SPIKE_PERF.md) §6.5.1 で確立した規律）。

> **計画では「フィールドを 5 種類足すと 2〜3 倍重くなる」と見積もっていた**（PLAN.md R-02）。
> 実測は 1.2〜1.4 倍。理由は単純で、**フィールドはヒットしたピクセルでしか走らない**うえ、
> 追加評価が約 22 回なのに対しマーチ自体がそれを大きく上回るため。
> → **540p へ落とす最終防衛線は不要になった。R-02 は完全に解消。**

## 2. 何をやっているのか

4 つのフィールドすべてが**距離場そのものから**導かれる。テクスチャもベイクも UV もない。

| フィールド | 導出 | 評価回数 |
|---|---|---|
| 法線 | 四面体サンプリングの勾配 | 4 |
| **カーバチャ** | 距離場のラプラシアン（凸が正、凹が負） | 4 + 1 |
| **AO** | 法線方向のコーンマーチ | 5 |
| **厚み** | 法線の逆向きに歩き、場が正に転じるまで | ≤ 8 |
| 上向き度 | 法線の Y 成分 | 0 |

これがメッシュに対する優位性そのもの。メッシュパイプラインは AO / カーバチャ / 厚みを
**テクスチャに焼く**しかなく、UV が要り、1 アセットあたり数分かかり、
**ジオメトリを変えた瞬間に陳腐化する**。ここでは既に呼んでいる関数を数回多く呼ぶだけなので、
**維持コストがゼロ**——ブーリアンを動かせば同じフレームで摩耗が追従する。

### 2.1 マテリアルの構成

| マスク | 条件 | 効果 |
|---|---|---|
| 摩耗 | 正のカーバチャ × 露出（AO） | 地金が出て磨かれる（粗さ 0.58 → 0.10） |
| 汚れ | 低い AO × 非凸 | 暗く、非金属化、粗さ 0.94 |
| 埃 | 上向き³ × 開けている × 摩耗していない | 明るく、非金属化、粗さ 0.96 |
| 透過 | 薄い部分 | わずかに暖色で発光 |

**摩耗が AO を掛けているのは意図的**。鋭い角でも、ボアの底なら誰も擦らない。
「エッジであること」と「手が届くこと」の積であることが、
結果を**フィルタではなく使用感**として読ませる。

## 3. 途中で潰した 2 つのバグ

どちらも**フィールドを直接可視化する**まで見えなかった。
`render_scene --fields` が各フィールドを単独で描く（`scene_fields_debug.hlsl`）。

> **マテリアルの数字をいじって絵が良くなるまで回すのは推測**である。
> 下層のフィールドが飽和していれば、いくらマテリアルを調整しても直らず、
> 調整はその歪みへの補償として積み上がる。**先にフィールドを見る**と、これが測定になる。

### 3.1 AO が正規化されておらず、溝が全部黒帯になっていた

```hlsl
occ += (h - d) * sca;          // occ は「長さ」の次元で累積する
return saturate(1.0 - 1.6 * occ / reach);   // ← reach で割るのは誤り
```

5 サンプルの重み付き和なので `occ` は最大 **2.14 × reach** に達する。
`reach` で割ると 1/3 進んだ時点で黒にクリップされ、**溝は階調のない平坦な暗帯**になった。

**修正**: 完全遮蔽時の値を同時に累積して割る。これで `occ/norm` が構造的に 0..1 に入る。

```hlsl
occ  += (h - d) * sca;
norm += h * sca;
return saturate(1.0 - 1.15 * occ / max(norm, 1e-6));
```

### 3.2 カーバチャの正規化長を手で選んだせいで、円筒側面が「摩耗した縁」になっていた

最初は `clamp(lap * refLength, -1, 1)`（`refLength` は手で決めた長さ）としていた。
結果、**半径 2 の円筒が 90 度の角と同じだけ飽和**し、フランジの外周全体が摩耗扱いになった。

**修正**: 正規化長を**サンプリング距離 `h` 自身**にする。

ラプラシアンは 1/長さ の次元を持つ。鋭い稜線では距離場に折れがあるので離散二階差分は **1/h** で増大し、
`h` を掛けると **h によらず order 1** になる。一方、半径 R のなだらかな曲面は **h/R** にしかならない。

```hlsl
return clamp(lap * h * 0.5, -1.0, 1.0);
```

**「稜線」と「なだらかな丸み」が構造的に分離され、しかもモデルごとの再調整が不要になる。**

## 4. D2：形を変えると摩耗が追従する

`tools/makescenes` が溝の半径だけを変えた 5 変種を生成する（`hero_sweep_0..4.gsf`）。
**マテリアルは 1 バイトも変えていない。モデルの数字が 1 つ動くだけ。**

| 溝半径 | 観察されること |
|---|---|
| 0.80 | ハブの根元に汚れが集中 |
| 1.11 | 溝が独立したリングとして見え、その両肩が磨かれる |
| 1.42 | **溝がボルト穴と交差し、その交点に汚れが溜まる**。摩耗リングが再編成される |

連番全体で摩耗パターンが完全に組み替わる。**これはベイクしたテクスチャには原理的にできない。**

出力: `spike/build/bin/weathered_hero_sweep_*.png`、まとめ画像 `sweep_montage.png`

## 5. ヒーローアセット

`tools/makescenes/MakeHeroAsset.java` が機械加工フランジを生成する（25 ノード → 23 ノード / スタック 5）。

形はフィールドが示すべきものから逆算して決めた：

- **鋭い凸稜線** — ハブの縁、ボアの口、ボルト穴の縁 → 摩耗が出る
- **丸められた外周** — トーラスで面取り → 摩耗が半径方向に減衰する様子が出る
- **深い凹部** — 環状溝とボア → AO が落ちて汚れが溜まる
- **広い上向き平面** — 埃が乗る
- **薄いウェブ** — 溝と裏側の逃げ穴の間 → 透過が出る

ボルト穴は**6 子の 1 つの `Merge`**。人がグループ化するならそうするし、
平坦化の平衡二分化が効くのもそこ。

## 6. 接地・流れ落ちる汚れ・サンプリング幅（Phase 4 後半）

3 点とも潰した。潰し方と、潰せなかった部分の理由を残す。

### 6.1 接地影 — 影は 2 本要る

床（`gGroundY` = モデルの底面）を解析平面として追加した。**CSG には入れていない**。
`evalCsg` に混ぜると全ジオメトリフィールドが床を見てしまい、
「無限に開けた上向き面」が真下にある扱いになって、部品が床の埃を被る。

床に落とすのは 2 種類の影で、**片方だけでは足りない**。

| 種類 | 由来 | なぜ要るか |
|---|---|---|
| **投影影** | キーライト方向へのソフトシャドウマーチ | 光の位置に依存する。今回の光は奥上手なので影は画面外に落ちる — **最初の実装はこれだけで、床に何も出なかった** |
| **接触項** | 床の点から部品表面までの距離（`evalCsg(floorPoint)`） | 光の向きに依存しない。部品の**真下**が暗くなる。これが「置いてある」を作る |

接触項は距離場そのものなので**追加コストが 1 evaluation**。
メッシュなら深度バッファをぼかして近似する部分である。

さらに**背景と反射環境を分離**した（`mkBackground` / `mkEnvironment`）。
反射環境は明るくないと磨かれた縁が何も映さず粘土になる。背景は暗くないと縁のコントラストが出ない。
分ける前は床を半径で切っても**背景と同じ灰色**なので見た目が変わらなかった。

### 6.2 汚れ — 溜まるだけでなく流れる

`(1 - 空遮蔽) × (1 - 上向き度²)` を汚れに加えた。
空遮蔽は**真上へのソフトシャドウマーチ 1 本**で、これも距離場だけから出る。

AO は方向を持たないので、庇の下の垂直壁を「開けている」と報告する（横には実際に開けている）。
方向を持つ空遮蔽だけがその差を見る。

**ただしマスクを強めても限界がある**ことは測って確認した。
旧ヒーローアセットには庇が無く、空遮蔽はリム全面で 1 だった。
そこで**アセット側に庇（`LIP_OVERHANG = 0.16`）と深い環状溝（0.08 → 0.14）を足した**。
溝はこれ以上深くできない — 0.22 にすると溝底がボルト穴の上端に達し、穴がスロットになる。

### 6.3 サンプリング幅 — カメラ距離に依存していた

`curvEps = gFarDist * 3.2e-3` の `gFarDist` は**カメラ距離 + マージン**である。
つまり**カメラを引くと摩耗帯が広がっていた**。材質はそんなことをしない。

`fields.hlsl` の `mkFieldScales(sceneRadius)` に集約し、全部モデル自身の大きさ基準にした。
既定のフレーミングでは同じ値になる（差分 921,600 画素中 209 画素）ので、
**見た目を変えずに依存だけ落とした**。

集約のもう一つの効果：`--fields` デバッグ表示は `curvEps = 1.2e-3`、
マテリアルは `3.2e-3` で**別々の値を使っていた**。
調整のために見ている絵が、調整している絵ではなかった。今は同じ struct から来る。

### 6.4 影 2 本のコスト

`pettobotoru`、min-of-25 を 3 回ずつ。

| | 最良 | 3 回の値 |
|---|---|---|
| 影なし | 8.94 ms | 8.94 / 9.24 / 9.30 |
| 影あり（48 段 × 2） | 12.64 ms | 12.64 / 12.87 / 13.01 |
| 影あり（キー 32 段 / 空 14 段） | 11.65 ms | 11.65 / 12.71 / 11.74 |

**+30%。** 段数を分けて 41% → 30% に落とした。空遮蔽はソフトマスクにしか入らないので粗くてよい。

> **1 回の計測では何も言えない。** 同一シーン同一ビルドで 6.8 ms 〜 44 ms まで振れた。
> このマシンの iGPU はクロックが上がりきるまで数十フレームかかる。
> `render_scene --repeat N` を足して**最小値と最悪値の両方**を出すようにした
> （SPIKE_PERF.md）。最小値自体は min-of-25 で ±1.5% に収まる。

## 7. 残っている調整点

- **汚れは依然として控えめ。** 庇と深い溝で改善したが、
  この部品は本質的に「機械加工された清潔な板」で、汚れの居場所が少ない。
  次に効くのはマスクではなく**アセットの形**（アンダーカット、リブ、段付きボス）
- **投影影が画面外に落ちる。** キーライト方向 `(0.45, 0.80, 0.40)` は
  見栄えのために選んだもので、影の見え方では選んでいない。D1 の構図を決めるときに再検討する
